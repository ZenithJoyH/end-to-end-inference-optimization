# 20260920-p4k-mbt32768-04 P4K token-budget 32768

- 状态：`complete/rejected`
- 分类：`framework`
- 目标场景：P4096/D1024/C64/N128
- 单变量：`max_num_batched_tokens=16384→32768`

## 优化方向与瓶颈依据

P4K trace 的 16 个 Mixed marker 中有 15 个每轮引入 4 个新请求，对应当前
`16384/4096=4` 的 admission 上限。Mixed 阶段累计设备活动远高于单独 Prefill/
Decode 窗口，首要活动为 Sparse MLA prefill 24.694% 和 fused MoE 22.019%。
把 token budget 翻倍预计允许每轮引入 8 个 prompt，减少 admission wave 及阶段
切换；是否转化为端到端吞吐必须由无 profiler 测量确认。

P1K 上同一变量曾因三轮 warmup 离散 17.771% 而失败，且后两轮没有超过保留
基线。本实验不复用该结论：P4K 的 prompt/budget 比例和 Mixed 波数不同，但采用
更严格的预调合同防止再次把冷态误当回归或收益。

## 优化内容与适用边界

只把服务启动参数 `max_num_batched_tokens` 从 16384 改为 32768；max64、TP16、
BF16、80K context、prefix cache disabled、FULL_DECODE_ONLY、源码和 FlagGems DB
全部不变。不修改交付启动脚本，候选失败可直接停止服务回退。

fresh service 执行 6 warmup + 3 measured：前三轮作为完整 P4K 预调，后三轮才
参与 5% 稳定性判断，最后三轮用于比较。这与 baseline 的三轮预调 + 独立 3+3
生命周期等价。

## 正确性与路径命中

启动前核验三个仓库 revision/dirty 集合、32768 cmdline、prefix cache 0、graph
服务和 DB SHA。九轮均要求 128/128 请求成功和指标有限；不引入新的数值实现，
沿用 172/198>=86% 的精度 gate。

实际 fresh graph 服务成功启动，身份清单 SHA-256 为
`88d786b2c9da50debcc29e8dc0b722780caf4e549cb182f8b48cedfaa5ff1323`。
九轮共 1152/1152 请求成功、0 失败，服务未重启，prefix cache 保持关闭。

## 性能效果

比较基线为 P4K 稳态 1071.417 output tok/s。三组冷态预调吞吐为
`978.950 / 1087.502 / 1046.481 tok/s`；稳定性窗口为
`1089.834 / 1090.242 / 1087.377 tok/s`，相对离散 0.263%，通过 5% 门禁。

最后三轮 measured 为 `1077.099 / 1083.146 / 1094.798 tok/s`，中位数与
基线比较如下：

| 指标 | 16384 基线 | 32768 候选 | 变化 |
|---|---:|---:|---:|
| 输出吞吐 | 1071.417 tok/s | 1083.146 tok/s | +1.095% |
| 总 token 吞吐 | 5357.084 tok/s | 5415.729 tok/s | +1.095% |
| 请求吞吐 | 1.04631 req/s | 1.05776 req/s | +1.095% |
| P99 TTFT | 24406.642 ms | 23282.646 ms | 改善 4.605% |
| P99 TPOT | 58.560 ms | 57.713 ms | 改善 1.448% |
| P99 ITL | 780.403 ms | 38.864 ms | 诊断值，不作主门禁 |
| P99 E2EL | 80029.985 ms | 72927.483 ms | 诊断值 |

measured 输出吞吐相对离散为 1.634%，九轮请求和服务健康门禁均通过；主指标
只有 +1.095%，低于预冻结的 +3% 晋级门槛。该结果表明翻倍 admission budget
可以稳定运行并略微改善吞吐/TTFT，但 profiler 中观察到的 wave 减少潜力没有
按比例转化成端到端净收益。

## 决定、风险与回退

决定为 `rejected`：不保留 32768，交付启动脚本及当前最优组合继续使用
`max_num_batched_tokens=16384`。候选服务已停止，未修改源码，不需要源码回退。
下一步按规划检查 P4K Sparse MLA prefill 的目标 shape 和已有 vendor 实现；只有
算子微基准形成至少 5% 的稳定候选，才进入 graph 与无 profiler P4K 端到端验证。
