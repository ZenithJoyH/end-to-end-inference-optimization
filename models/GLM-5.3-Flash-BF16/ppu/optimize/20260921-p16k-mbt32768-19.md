# 20260921-p16k-mbt32768-19 P16K token budget A/B/R

- 状态：`complete_retained`
- 分类：`framework`
- 最终目标：`P16384/D1024/C64/N128`
- 首个证伪里程碑：`P16384/D128/C64/N128`
- 单变量：`max_num_batched_tokens=16384→32768`

## 优化方向与瓶颈依据

P16K 16-rank trace 中 rank0 共有 63 个 Mixed marker，每波都是
`execute_new_1_cached_{1..63}`。当 token budget 与 prompt 长度同为
16384 时，调度器每轮只能引入 1 个新请求，使 Prefill 与已在
Decode 的请求持续交叉。提高到 32768 理论上可每波引入 2 个新请求。

P4K 同变量只有 +1.095% 的反证，因此不直接将配置写入交付
脚本，先用缩短 Decode 的 P16K milestone 做完整 A/B/R。

## 优化内容与适用边界

baseline/revert 使用 MBT16384，candidate 使用 MBT32768；其他
TP16、BF16、max64、max-model-len80000、FULL_DECODE_ONLY、前缀缓存关闭、
源码和 DB 身份全部一致。每个角色在 fresh service 上运行 6 warmup +
3 measured，前 3 轮只用于冷 shape 预调，第 4–6 轮作为稳定窗。

## 正确性与路径命中

三个角色均要求 graph 服务健康、prefix cache query/hit 为 0、每轮
128/128 请求成功、必需指标有限、源码与 DB SHA 不变。本点不改
模型语义，复用已通过的 `172/198=86.87% >= 86%` 正式精度 gate。
完整候选服务上固定 C1 为 1/1、C8 为 8/8，结果 SHA-256 分别为
`99728d0e35290321bce143aa223e8ff5688a4b6256e0aa4a6956b0afc300de17`
和 `34fb618e8c9eb63bb30e394f65c3830cf2758d532248d9c858ca940763bc1cba`。
