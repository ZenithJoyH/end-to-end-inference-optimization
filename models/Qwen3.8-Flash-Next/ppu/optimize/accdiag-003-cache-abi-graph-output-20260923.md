## Completed controlled experiments and decision

The cache-ABI patch applied only to the private Plugin copy, explicitly adding QSA main/raw/compressed caches and PLE convolution state to their custom-op arguments and `mutates_args`, without changing the underlying math. Source SHA-256 changed from `3ae84180f7b5f4d70886c98f1d1afcf2255f8f7223a110397ec4894cf81a9a59` to `bfc07077b7f578550edd1c219bb2d062f30e469fa262eee29e1294ca8a30fe1e`; graph capture, readiness and 24/24 short requests passed. On 8000, five of six 64-token trajectories changed against the byte-identical private r2 baseline. After a hash-guarded source revert and service restart, **all six** returned exactly to the private r1/r2 trajectory. The concurrent 8010 output remained identical in every stage. This is strong evidence that the custom-op dependency declaration changes deterministic execution, but cross-port agreement changed from 3/6 to only 2/6, not an improvement. The patch also reduced reported GPU KV cache capacity from `2,771,086` to `2,029,364` tokens (~26.8%); the reverted service returned to `2,771,086`. This is an operational regression for long responses, not a demonstrated accuracy fix. No formal GPQA score can be assigned to this 64-token probe.

The second, isolated graph-output patch used the historical non-owning CUDA view construction only on the private copy. A small GPU check proved the current installed vLLM weak-ref path returns the **same Tensor/storage**, whereas the patched path returns a different Tensor/storage pointing at the same data. The source graph SHA-256 changed from `ba78ed0a736bb21a4f2c307fc9775f15e3742b94533eff333b0c364eb8213fc2` to `47dda1227991faab1c20a107693b234bf7b84592bd25c2707bc16908c0d23add`. Despite this semantic change, 8000's six short trajectories were byte-identical to the baseline before the patch and after a hash-guarded revert; graph capture, 24/24 probe requests and health passed. It does not explain the tested early-token differences, although a long-horizon lifetime effect is not ruled out by this short test.

Both diagnostic patches were reverted in the private copy. The 8000 service was restored to `/workspace/vllm-plugin-FL-qwen38-adaptation` with its original argv, settings and cards 8–15. Its final host PID/start ticks were `2996435/286427952`; the untouched 8010 reference retained start ticks `284523170`.
